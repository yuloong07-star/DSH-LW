# 日程 (lw_calendar 版)

日程在系统日历数据库里, 只有 `lw_calendar` 这条工具读得到、写得到 —— 会话自己的文件工具碰不到它。

## 六条 op

| op | 拿它做什么 | 必给的参数 |
| :-- | :-- | :-- |
| `list` | 先调它一次: 有哪几本日历, 哪几本**可写** | 无 |
| `events` | 查一段时间里有什么 | `from` `to` (可选 `calendarId` / `limit` 默认 50 / `query`) |
| `read` | 读一条的全文 (连备注) | `eventId` |
| `create` | 建一条 | `title` `start` (可选 `end` 或 `durationMinutes` 默认 60 / `calendarId` / `location` / `description` / `allDay`) |
| `update` | 改一条 (只改你给的那几个字段) | `eventId` |
| `free` | 一段时间里的空档 | `from` `to` (可选 `minMinutes` 默认 30 / `dayStart` 默认 09:00 / `dayEnd` 默认 22:00) |

## 时间怎么写

- 两种都认: `2026-10-09T14:00` (本地时间) 或 epoch 毫秒; **回执两种都会给你**
- 时区就是**设备时区**, 不用转换; 用户说"下午三点"就是本地下午三点
- 用户说"明天""下周三"这类相对说法, 先用当前日期算出确切日期再调工具, 不要把它原样传进去
- 跨天活动给 `start` 与 `end` 两个完整时刻; 整天的活动用 `allDay: true` 并在时间上取当天零点

## 查

1. **先 `list`**: 拿 `calendarId` 与"可写不可写"; 只查不问日历就不给 `calendarId` (会查全部)
2. 查"哪天有空": 用 `free`, 窗口给足 (例: 从明天 09:00 到周日 22:00), 它按 `minMinutes` 把不够长的缝
   滤掉 —— **报空档时报确切区间**, 不要只说"那天有空"
3. 查"有没有冲突": `events` 拿那一段的条目, 与要放的时间比一下; 重叠就明说与哪一条重了
4. 一天里的事件可能很多: 一次给的窗口别超过两周, 要更长的分几次查 (一次最多 50 条)

## 写 (这一节是红线)

1. **含糊先问**: 主人没点名日期 / 时间 / 时长时, 先问一句最关键的 (哪天? 几点?), 不要自己挑一个时间
   塞进去; 主人点名了就**直接写**, 不要为了"确认"再问一遍同一件事
2. 写之前先 `events` 看一眼有没有撞车, 撞了就明说并给最近的空档
3. **落到哪本**: 不指定就是第一本可写日历; 主人说过"记到工作日历 / 家庭日历"时先 `list` 找到那一本再指定
   `calendarId` —— 名字对不上时如实说, 不要随便挑一本
4. **写完回读**: `create` 回执里的 `eventId` 与起止时间照抄给主人 (哪一天、几点到几点、写进哪本日历)
5. 改一条先 `read` 一次看当前值, 只把要改的字段传进去; 删一条**没有这条工具** —— 主人要删就说清
   本机做不到, 请到日历应用里删
6. 日程正文里**不写密码、验证码、密钥**; 别人的私事 (体检结果之类) 原样记, 但不主动复述

## 报的时候

- 报时间用"周几 + 日期 + 几点", 例: `周五 10-09 14:00-15:00`; 别只给 `2026-10-09T14:00:00+08:00`
- 一条一条列, 每条一行; 超过 5 条时先给一句总览 ("今天 4 条, 上午两场会") 再列
- 空就是空: "这段时间没有日程"与"读不到日程"是两件事, 后者要如实说并说清是缺哪条权限
