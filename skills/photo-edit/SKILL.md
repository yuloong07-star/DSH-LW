# p 图 (lw_image + edit_image 版)

一句话: **图从哪儿来** (`lw_image op=ref`) → **谁改图** (生图插件的 `edit_image`, 走主人在「设置 → 生图配置」里配的那条 API) → **成图去哪儿** (`lw_image op=album`, 进相册并打开)

改图那一步不由本机做, 也不由你画: 你要做的是把那句话翻成一句改图提示词, 把源图引用原样递上去, 再处理结果

## 四步

1. **认图** —— 图有三个来处, 按主人怎么说挑一个

   | 主人怎么说的 | 调什么 |
   | :-- | :-- |
   | 「这张图 / 这个 / 屏幕上这个」, 手里拿着手机 | `lw_image {op:"ref"}` —— 缺省就拍**他自己那块屏** (displayId 0) |
   | 会话里带着一张图 (他自己发的照片) | `lw_image {op:"ref", from:"conversation"}` |
   | 给了一个工作区里的文件路径 | `lw_image {op:"ref", path:"..."}` |

   这三种都不要先 `lw_screenshot` 再想别的: 这一条自己会拍那一张, 拍的是**全分辨率那一份** (不走"给模型看的预算"), 因为它的去处是上游生图接口而不是模型上下文。只有图确实在一块虚拟屏上时才 `displayId` 指那块屏

2. **改图** —— `edit_image`, `prompt` 就是主人那句话的意思 (他怎么说就怎么写, 不要加他没要求的东西), `source_image` **原样**放上一步那一整个对象

   - 没配渠道时它回的是 `image-api-not-configured` 这类: 如实转告主人去「设置 → 生图配置」加渠道、填 API 地址与密钥, **不要试着自己拼一个 HTTP 请求绕过它**
   - 有多个模型而没有缺省时它会让你问主人要哪一个: 就照它说的问一句
   - 一次只改一处: 主人说了两处就分两次改, 或者先改最要紧的那一处并说清还有一处没动
   - 它默认等到任务出结果 (最多 5 分钟) 才返回, 所以这一句不用你轮询

3. **成图进相册** —— 上一步的答案里每一张都有 `attachment_id` / `media_type` / `bytes` / `width` / `height`。取第一张 (主人点名要几张就几张), `lw_image {op:"album", image:<那一整个对象>}`: 它拷一份进相册 `Pictures/DSH-LW` 并顺手在屏上打开

   - 还要接着改 (迭代): 把上一张的引用原样当 `source_image` 再调一次 `edit_image`, 改完照旧进相册 —— 每一版都留一份, 不覆盖上一版

4. **回报** —— 一两句: 改了什么、图在相册哪儿、已经打开了。回答会被念出来, 所以结论说在前面

## 红线

1. **不许说"改好了"而其实没调 `edit_image`**: 本机没有第二个改图的地方, 你一个像素都画不出来
2. **不许改 `source_image` 里任何一个字段**: 那个对象是附件库的原话, 抄错一个数就是用错图或者直接被拒
3. **不许自己编 `attachment_id`**: 编出来的 id 一定读不到, 而报错会发生在附件库里, 与真正的原因差着一层
4. **上游接口是要花钱的**: 同一张图改一次就够, 不要连着提交几遍; 主人没要求时不要一次要四张
5. **图会发到主人配的那个 API 服务**: 问起来就如实说, 不要承诺"只在本机处理"
6. **相册那一份不是唯一一份**: 工作区 `pictures/` 下也留着一份 (模型手里要有一个能指的路径), 主人问文件在哪时两个都可以说

## 与本机别的东西的分工

| 要什么 | 谁做 |
| :-- | :-- |
| 从零生成一张新图 (没有源图) | 生图插件的 `generate_image` (同一个插件的文生图那一半) |
| 改一张已经有的图 | `edit_image` (本技能第 2 步) |
| 看屏 / 读屏 (不改图) | `lw_screenshot` / `lw_ui` / `lw_ocr`, 与本技能无关 |
| 让相册看见一个已经在工作区里的文件 | `lw_media_scan` —— 它只是"请系统索引一下", **不搬文件** |
| 把成图放进相册并打开 | `lw_image {op:"album"}` (本技能第 3 步) |
| 渠道配置 / 画廊 / 无限画布 / 提示词模板 | Web GUI 侧边栏「生图」, 主人自己在界面里用 |

## 三个已知的坑

- **生图插件那一行没起来时, 整块能力都不在** (它的工具注册在一起): 启动日志里那一行会写着 `did not activate`, 会话里 `generate_image` / `edit_image` 一个都没有。那时如实说"生图插件没起来"并让主人重开会话或重启 host (设置页右上角 ⋮ 里那条), 不要拿别的工具硬凑一个"差不多"的结果
- **`generate_image` 不认源图**, 它是文生图: 要改现有的图就得走 `edit_image` + `source_image`
- **拍屏拍的是主人此刻看到的东西**: 他要是先切走了, 拍到的就是新界面。主人说「这张图」而屏幕上已经明显不是他指的那个时, 先说一句你看到的是什么再动手, 不要闷着改一张错图
